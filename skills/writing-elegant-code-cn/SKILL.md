# 编写优雅代码

以“收敛”为准则：直接形成最终设计，不把临时态、迁移层或补丁留在代码库中。

## 注释

- 优先用职责清晰的拆分和准确命名让代码自解释。
- 只在代码无法表达决策时解释“为什么”：外部约束、反直觉行为或重要权衡。
- 删除复述“做什么”、描述显而易见流程或已经失效的注释。

## 设计

- 从根因和正确抽象处修改，使实现收敛为完成当前需求所需的最少概念和单一路径。
- 在同一次改动中移除被替代的逻辑；每个中间层、分支、特例和扩展点都必须有当前需求作为依据。
- 兼容路径只服务于明确要求或已验证的外部契约，并与正常路径保持清晰边界。
- 彻底修改本次需求触达的抽象；无关区域保持原样。

## 类型

- 让精确类型贯穿输入边界、内部流转和输出边界；在边界处验证不可信数据后再使用。
- TypeScript 中不写显式或隐式 `any`。类型未知时使用 `unknown`，通过类型守卫或 schema 校验缩窄后再传递。
- 仅在已由运行时检查或明确不变量证明安全时使用类型断言和非空断言。

## 库

- 实现已有成熟实践前，先检查项目现有依赖和生态方案；优先复用维护活跃、应用广泛的成熟库。
- 新增库时使用与项目运行时、工具链和 peer dependencies 兼容的最新稳定版本，并依据当前文档使用其 API。
- 优先复用项目中已有的现代库，避免为同一能力引入重复依赖；几行清晰的领域逻辑直接实现。

## 完成门槛

完成前逐一检查每个修改文件：

- 每条注释都通过“为什么”测试。
- 每个新增概念和逻辑路径都有当前需求；被替代的实现已移除。
- TypeScript 中没有 `any`，所有 `unknown` 都在使用前完成缩窄。
- 成熟能力已交给合适的库，或自实现确实更小、更清晰。
- 相关类型检查、lint 和测试通过。
